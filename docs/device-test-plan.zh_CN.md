# 真机测试用例

用这份清单在真实设备上验证「奥特曼诗词收集冒险」。刷写属于破坏性操作，必须先取得明确同意，
再按根目录 README 的说明从 `0x0` 写入合并镜像；未经单独确认不要执行整片擦除。

## 前置条件

- ESP32-C3 AI Passport，屏幕（240 × 320）、三颗按键、扬声器与 CW2017 电量计工作正常。
- 本仓库的 ESP-IDF 5.5.3 构建产物，或已发布的 `FoloToy-AI-Passport-full.bin`。
- 供电稳定：电量充足的电池，或可传数据的 USB 连接。
- 记录每一步的结果，便于失败时复现。

## 测试用例

| 编号 | 范围 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| D01 | 开机 | 上电，等待首屏出现。 | 首页显示水墨山水、Q 版奥特曼、冒险标题、四个菜单项、电量百分比与底部提示。无黑屏、闪烁循环或反复重启。 |
| D02 | 菜单导航 | 在首页反复按 UP、DOWN。 | 高亮在四个菜单项之间双向循环，每次移动播放轻柔提示音。 |
| D03 | 进入地图 | 选中第一项「继续冒险」，按 OK。 | 打开诗篇地图，显示三张带编号的卡片、场景名、诗名、收集计数，以及正确的「已收集 / 待收集」状态。长按 OK 返回首页。 |
| D04 | 诗篇序章 | 进入第 1 关，阅读序章。 | 显示该关场景、Q 版奥特曼、场景名、诗名、朝代与作者、序章文案，文字不截断、不重叠。OK 开始挑战；长按 OK 返回地图。 |
| D05 | 字块排序 | 进入第一项挑战。按 OK 拿起一个字块，移动后再按 OK，最后移到「检查」按 OK。 | 第一次 OK 高亮被拿起的字块，第二次 OK 与光标处交换；「检查」提交排序。顺序正确时进入第 2/4 项挑战。 |
| D06 | 温和提示 | 故意连续提交两次错误排序。 | 第一次答错只播放轻柔提示音，棋盘仍可编辑；第二次答错在提示条显示诗句线索。不出现生命值、倒计时或失败结算。 |
| D07 | 下一句接龙 | 完成第 1 项后作答第 2 项。 | 顶部显示「2/4」和对应挑战名。当前诗句、三个选项与提示条清晰可读。答错可重试，答对进入第 3/4 项。 |
| D08 | 看画猜诗 | 打开第 3 项，观察插画与选项。 | 全屏国风场景完整显示在三个诗名选项上方，Q 版奥特曼不遮挡选项，底部提示或线索仍可读。 |
| D09 | 补全诗句 | 作答第 4 项。 | 诗句中出现明显的空缺，三个汉字选项足够大，答错后仍可重新选择。 |
| D10 | 收集奖励 | 完成第 4 项挑战。 | 奖励页展示完整诗句、朝代与作者、白话解释、Q 版奥特曼和收集提示。整诗普通话朗读开始播放，并播放解锁提示音。 |
| D11 | 写入图鉴 | 离开奖励页，回到首页，打开第二项「光之诗库」。 | 已收集诗篇显示诗名、作者与场景；未收集诗篇显示锁定占位，不能打开。 |
| D12 | 图鉴重读 | 从图鉴打开一首已收集的诗。 | 详情页显示完整诗句与解释。按 OK 重听朗读，长按 OK 返回图鉴。 |
| D13 | 断电记忆 | 关机，等待片刻，再开机。 | 收集计数与图鉴条目保持；已解锁的诗不会重复播放解锁故事。 |
| D14 | 微故事解锁 | 依次收集第 1、2、3 首诗。 | 每首新收集的诗之后出现一段奥特曼小故事（阈值为 1、2、3）。按 OK 继续，长按 OK 返回地图。 |
| D15 | 速答挑战 | 打开第三项「速答挑战」。 | 共 5 题，逐题显示 15 秒倒计时条、得分与进度。作答后自动进入下一题，第 5 题后出现结算页。长按 OK 可提前退出。 |
| D16 | 速答超时 | 在速答模式中等待倒计时归零。 | 该题判为答错，播放轻柔提示音，并自动进入下一题，不卡死。 |
| D17 | 静音 | 切换首页第四项「音效」，再答题或收集，最后重启。 | 标签在「开启 / 关闭」之间切换；关闭后提示音静音；重启后保持该设置。 |
| D18 | 混音 | 在奖励页或图鉴详情页播放朗读，仔细听。 | 朗读清晰；朗读期间背景音乐明显降低音量；交互提示音不会切断朗读。 |
| D19 | 长按返回 | 依次在地图、序章、挑战、奖励、图鉴、图鉴详情、故事、速答页面长按 OK。 | 每个页面都返回文档规定的上级页面，不残留朗读或背景音乐，界面不失去响应。 |
| D20 | 电量显示 | 在首页、地图、奖励、图鉴与速答页观察电量百分比。 | 数值在数秒内刷新，且不与标题、得分或进度点重叠。 |
| D21 | 稳定性 | 连续游玩三关、速答模式，并多次重读图鉴，持续至少 10 分钟。 | 无看门狗复位、内存耗尽、音频卡死或花屏；按键始终响应。 |

## 通过标准

逐项记录结果。所有用例为 PASS，或维护者明确接受已记录的偏差，才视为候选版本通过。
交付时分开报告：

```text
Build: PASS / FAIL / NOT RUN
Host tests: PASS / FAIL / NOT RUN
Device tests: PASS / FAIL / NOT RUN
Unverified: 仍需确认的板级、仪器或用户检查
```

## 失败记录

请写明用例编号、完整按键顺序、屏幕上的实际表现、是否涉及音频，以及断电重启后是否仍能复现。
如需提供日志，只截取相关行，并在分享前移除个人数据与凭证。
