# 与数学匹配游戏的玩法差异

本应用复用了 AI Passport 的 BSP、三按键输入链路、显示管线，以及
[leftstick/ai-passport-match-ultraman](https://github.com/leftstick/ai-passport-match-ultraman)
中的通用像素绘制思路；但决定「玩家做什么、一轮怎么结束、跨会话记住什么」的部分全部重做。
下表是这次重做的边界契约。

## 逐项对比

| 维度 | 数学匹配游戏 | 奥特曼诗词收集冒险 |
| --- | --- | --- |
| 核心目标 | 在限时或生命耗尽前，尽可能多地消除等值算式卡牌。 | 每个关卡重新拼出并收集一整首诗。分数不是目标。 |
| 单轮结构 | 在计分循环里反复进行短促的卡牌匹配。 | 序章 → 四种不同的收集挑战 → 整诗奖励 → 写入图鉴。 |
| 主要输入 | 在卡牌网格上移动光标，选中两张匹配的卡。 | 在有序字块或三个选项中移动光标；每种挑战的版面结构都不同。 |
| 题目内容 | 算式与等值结果。 | 古诗字块排序、下一句接龙、看画猜诗名、补全缺字。 |
| 失败处理 | 错误匹配消耗时间或生命，整轮可能结束。 | 主线没有生命、没有倒计时，也不会因答错结束。答错可重试，同一题第二次答错自动给出诗句线索。 |
| 节奏 | 快节奏、街机式重复。 | 慢读节奏：场景开场白、一关一首诗、可重听朗读，不催促快速作答。 |
| 难度来源 | 卡牌数量、时间限制与分数压力。 | 诗句长度与挑战类型；同一首诗可以无惩罚地反复进入。 |
| 附加模式 | 围绕同一卡牌循环的限时 / 无尽匹配。 | 可选的 15 秒速答复习，只用于巩固；主线冒险仍是主体验。 |
| 成长反馈 | 最高分与单轮统计。 | 已收集诗篇图鉴、收集 1/2/3 首时解锁的奥特曼微故事、单篇重读。 |
| 视觉语言 | 卡牌网格、街机 HUD、怪兽与光束特效。 | 水墨山水背景、诗句面板、印章红点缀、Q 版奥特曼向导；没有卡牌网格，也不复用 demo 菜单外壳。 |
| 音频语言 | 街机光束、怪兽咆哮与短促得分音。 | 整诗普通话朗读、五声音阶国风循环背景、五个轻柔交互提示音；朗读时背景自动降低音量。 |
| 持久化 | 最高分与单轮相关状态。 | 已收集诗篇位图、已解锁故事位与静音偏好，保存在 NVS 命名空间 `poem_adv_v1`。 |
| 复用边界 | — | 仅复用 BSP、按键事件框架、显示管线与像素绘制；玩法状态机、页面、布局、题目生成、音频混音与素材均为新实现。 |

## 明确不继承的部分

- 没有卡牌网格、配对消除与算术题。
- 没有生命值、连击槽、Boss 血条、光束节奏 QTE 或分数优先的胜利结算。
- 不复用上游 demo 菜单、页面外壳，也不复用数学游戏的视觉布局。
- 答题反馈不再使用怪兽咆哮或街机光束音；新反馈以平静、提示性为主，让答错不像惩罚。

## 为什么适合目标玩家

目标玩家是喜欢奥特曼、刚开始接触古诗的七岁孩子。设计保留熟悉的三按键操作，
但把情绪循环从「守住分数」换成「帮奥特曼把诗拼回来」：每答对一步，故事就向前走一步；
奖励是完整的诗和一段白话解释，而不是一个数字。

## 验证锚点

- `main/core/adventure.c` 固定四步顺序和「第二次答错给提示」规则；
  `tests/test_adventure.c` 对二者做断言。
- `main/core/poem_challenge.c` 生成并校验四种挑战；
  `tests/test_poem_challenge.c` 覆盖排序、选项、缺字与提示。
- `main/core/collection.c` 负责收集位图与故事位图；
  `tests/test_collection.c` 覆盖序列化与故事解锁阈值。
- `tools/check_assets.py` 强制校验三张场景、三张 Q 版立绘、三段朗读和五个提示音，
  确保新呈现方式不会在后续改动中退化。
